# Mago rules

Custom linter rules for [Mago](https://mago.carthage.software), that are used in [simbiat.eu](https://github.com/Simbiat/simbiat.ru) project. It is a port of the PHP Code Sniffer [sniffs](https://github.com/Simbiat/sniffs) (`simbiat/sniffs`) to the Mago extension API. Mostly generated by Claude.ai, with some cleanup and testing done afterward.

All rules are *linter* rules: each of them needs only the syntax tree of one file, none needs types or the analysis of several files, so there is nothing for the *analyzer*.

## What's in here

All rules are `warning` by default and are enabled by default. The level and the state can be changed in `mago.toml` by the code of the rule.

| Rule                                   | Description                                                                                                                                                                                                                                                                                                                                                                                             | Fixable? |
|----------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------|
| `simbiat/prefer-multibyte`             | Recommend using multibyte (`mb_*`) functions instead of single-byte functions. Useful for projects that deal with multi-language strings and emojis. Using arguments with a name that contains one of `binary`, `blob`, `bytes`, `raw`, `hash`, `digest`, `checksum`, `signature`, `ciphertext`, `plaintext`, `salt`, `iv`, `key` as a whole word (for example `$rawBody`, `$user_key`, `$hashes`, but not `$archive`), will serve as a hint, that this is binary data, and thus suppress the rule. | No       |
| `simbiat/multibyte-encoding`           | Highlights `mb_*` calls missing an explicit encoding. `UTF-8` is recommended in most modern environments.                                                                                                                                                                                                                                                                                               | Yes      |
| `simbiat/exit-code`                    | Suggests adding a status code to `exit`/`die` without one for the sake of being explicit.                                                                                                                                                                                                                                                                                                               | Yes      |
| `simbiat/prefer-white-string`          | Suggest using `\Simbiat\StringHelpers\Sanitize::whiteString($string)` call instead of `preg_match('/^\s*$/', $string) === 1` to capture more whitespace characters.                                                                                                                                                                                                                                     | No       |
| `simbiat/twig-safe-filter-option`      | Highlights `new TwigFunction(...)` / `new TwigFilter(...)` with `is_safe` flag. Using the flag bears risks, so you may want to ensure, that the function/filter is sanitized enough.                                                                                                                                                                                                                     | No       |
| `simbiat/sql-prefer-current`           | Prefer `CURRENT_*` functions in SQL literals instead of `UTC_*` ones. `UTC_*` bypasses whatever timezone you are using on the server, and unless it is already `UTC`, can result in time-related bugs. This rule helps with that, even if you do not use `UTC` as default timezone (which you should).                                                                                                   | Yes      |
| `simbiat/sql-missing-precision`        | Enforce explicit precision argument for date and time functions in SQL literals. `0` by default, see `--sql-precision` below.                                                                                                                                                                                                                                                                           | Yes      |
| `simbiat/missing-unicode-flag`         | Highlights `preg_*()` literal patterns missing the `u` flag. Useful in projects dealing with unicode.                                                                                                                                                                                                                                                                                                   | Yes      |
| `simbiat/missing-caseless-restrict-flag` | Highlights `preg_*()` literal patterns that have both `u` (`PCRE_UTF8`) and `i` (`PCRE_CASELESS`) but not `r` (`PCRE2_EXTRA_CASELESS_RESTRICT`) to prevent matching of `K` (Kelvin character), when you are searching for `k` and `K`. Results in stricter matches.                                                                                                                                     | Yes      |

## Installation

```shell
composer require --dev simbiat/mago-rules
```

Then add the extension host to `mago.toml` (see `mago.example.toml`):

```toml
[extension-hosts.simbiat]
command = ["php", "vendor/simbiat/mago-rules/bin/worker.php", "--sql-precision=0"]
```

Mago starts that command, and the rules run inside of that PHP process. It must be a PHP (8.4+) that can load the project's `vendor` folder: if your tools run in a Docker container, the command has to start the worker there (for example with `docker compose exec -T`).

`mago extension list` shows the rules that Mago loaded, and `mago extension validate` starts the worker and checks the registration.

### Settings

Mago has no per-rule options for extensions, so the settings of a rule are options of the worker command:

| Option            | Default | Was                                             | Meaning                                                                         |
|-------------------|---------|-------------------------------------------------|---------------------------------------------------------------------------------|
| `--sql-precision` | `0`     | `precision` property of `Simbiat.SQL.DateTimeFunctions` | Fractional-second precision for `simbiat/sql-missing-precision`. Values outside of 0-6 are moved to the nearest one. |

The level of a rule, whether it is enabled and the paths it skips are the normal `[linter.rules]` settings:

```toml
[linter.rules]
"simbiat/prefer-multibyte" = { enabled = false }
"simbiat/exit-code" = { level = "error" }
```

### Ignoring a result

Use the normal Mago pragmas, with the new codes: `// @mago-ignore lint:simbiat/missing-unicode-flag` and `@mago-expect`.

### Fixing

`mago lint --fix` applies the fixes of one pass. `mago fix` repeats until nothing changes. Use it, when a fix of one rule makes a fix of another possible (`u` flag, then `r` flag).

## Testing

```shell
composer install
vendor/bin/phpunit
```

The tests run the **real `mago` binary** (`vendor/bin/mago`, or the path from the `MAGO_BIN` environment variable) with this package as the extension. The rules run in a worker process that Mago starts, and a rule cannot be called from a test directly. PHPUnit cannot see this process, so when you collect code coverage (`vendor/bin/phpunit --coverage-text`), the test code does it for the worker: `tests/Support/WorkerCoverage.php` starts coverage inside each worker (`tests/Support/worker-coverage.php`) and merges the data into the report of PHPUnit. You need a coverage driver (pcov or Xdebug) in the `php` that Mago starts. Without coverage, nothing changes. Because of the strict coverage metadata, each test class names its target (`#[CoversClass]`, `#[UsesClass]` or `#[CoversNothing]`).

Each fixture folder has a test class in `tests/<Category>/<Name>Test.php` and fixtures in `tests/Fixtures/<Category>/<Name>/*.inc`. The test class names the codes of its rules. `tests/RuleTestCase.php` does the rest: it runs **only those rules** on every fixture (`mago lint --only`) and compares the results to the directives written in the fixture (all in `//` comments):

| Directive                         | Meaning                                                                                                          |
|-----------------------------------|------------------------------------------------------------------------------------------------------------------|
| `// @expect code-a code-b`        | This line must give these results (codes of rules). A line without `@expect` must give **no** result.             |
| `// @expect-next code-a`          | The next line must give these results. Use it for multi-line strings and heredocs.                               |
| `// @expect+2 code-a`             | The same, N lines below.                                                                                         |
| `// @property precision=N`        | Set `--sql-precision` of the worker for the whole fixture.                                                       |
| `// @max-passes N`                | The fixer may need N runs of `mago lint --fix` for this fixture (default: 1).                                    |
| `// @known-issue Text`            | The fixture describes **desired** behavior that the rule does not have yet. Tests are "incomplete", not failed.  |

If `Fixture.inc.fixed` exists, the fixer output must be equal to it. If it does not exist, the fixer must not change the fixture. Fixer output must always be valid PHP, and must not have fixable results left.

To add a rule: create the rule, register it in `MagoExtension.php`, add it to the table above, then add a test class and at least one fixture. `tests/ExtensionTest.php` fails until all of these exist, and until Mago itself lists the rule.
